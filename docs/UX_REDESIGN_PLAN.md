## 1. 기획 의도와 현재 UI의 차이

PRD의 핵심 문장은 "데이터 → 설계 → 액션까지 하나의 흐름"이다. 재난을 **보고**, 상황을 **이해하고**,
복구안을 **설계하고**, 도움을 **연결**하는 네 단계가 끊기지 않아야 한다.

현재 UI는 이 네 단계를 각각 다른 메뉴로 만들어 놓았다. 기능은 대부분 구현되어 있지만 화면끼리
이어지지 않는다.

| PRD의 단계 | 현재 위치 | 끊기는 지점 |
|---|---|---|
| 본다 | Home(지도), Events, Overview | 세 화면이 같은 데이터를 다른 필터·다른 숫자로 보여 준다 |
| 이해한다 | 이벤트 상세 | 빈 섹션이 화면의 절반 이상이고, 다음에 할 일이 맨 아래에 있다 |
| 설계한다 | Plan, Challenges | 어떤 재난을 위한 설계인지 모르는 채 임의의 도시에서 시작한다 |
| 연결한다 | Connect | 재난과 무관한 빈 목록으로 시작하고, 흐름 설명이 없다 |

**설계 방향 한 줄 요약: 메뉴 중심 구조를 재난(이벤트) 중심 구조로 바꾼다.** 사용자는 재난 하나를
고르고, 그 재난 안에서 상황을 읽고, 필요를 확인하고, 설계하고, 돕는다.

### 1.1 UX 원칙 (충돌할 때의 판단 기준)

1. **재난이 중심이다.** 모든 행동(돕기, 설계, 알림)은 특정 재난이나 지역에서 시작한다.
2. **중요한 것이 먼저 보인다.** 정렬과 크기와 색은 심각도와 피해 규모를 따른다. 최신순은 보조다.
3. **모르는 것을 0으로 쓰지 않는다.** 데이터가 없으면 "집계 전"이라고 쓰고, 화면에서 자리를 줄인다.
4. **색은 한 가지 뜻만 가진다.** 색은 심각도, 모양·아이콘은 재난 유형이다. 예외를 두지 않는다.
5. **아이콘만 있는 버튼을 만들지 않는다.** 지도 위 도구는 이름이 보이거나, 최소한 툴팁과 접근성 이름이 있다.
6. **느린 기기와 작은 화면이 기본이다(PRD NFR-6).** 모바일에서 지도를 가리는 것은 한 번에 하나만 띄운다.
7. **7개 언어를 모두 지킨다.** 새 문구는 `lib/i18n/locales/*.ts` 7개 파일에 모두 넣는다. 아랍어는 RTL이다.

## 3. 사용자 흐름

PRD 4장의 페르소나를 과업으로 바꾼 것이다. 각 흐름은 3번 이내의 선택으로 끝나야 한다.

| 사용자 | 하려는 일 | 새 흐름 |
|---|---|---|
| 기관 담당자 | 지금 가장 심각한 재난과 그 상황 파악 | 지도(심각도 색) → 마커 → 요약 패널 → 재난 상세 "상황" 탭 |
| 후원자·봉사자 | 어디에 무엇이 필요한지 보고 돕기 | 참여 → "도움이 필요한 재난" → 재난 상세 "필요와 지원" 탭 → 지원 제안 |
| 엔지니어·디자이너 | 특정 재난의 부지 설계 | 재난 상세 "설계" 탭 → 부지 계획 시작(재난 위치로 지도 이동) → 저장·공유 |
| 현지 파트너 | 필요 등록, 소식 올리기 | 로그인 → 내 단체 → 재난 선택 → 필요 등록 |
| 지역 주민 | 내 지역 재난 알림 | 재난 상세나 지도에서 "이 지역 알림" → 범위 확인 → 완료 |

모든 흐름이 **재난 상세 화면**을 지난다. 그래서 이 화면을 허브로 다시 만든다(5.3).

## 4. 정보 구조

### 4.1 상단 메뉴

7개를 4개로 줄인다. 주소(URL)는 바꾸지 않는다.

```
[Phoenix]  지도   재난   참여 ▾   현황        [검색]   [🔔]  [계정 ▾]
                         ├ 필요와 지원     (/connect)
                         ├ 부지 설계       (/plan)
                         └ 설계 공모       (/challenges)
```

| 지금 | 바꾼 뒤 | 이유 |
|---|---|---|
| Home | 지도 (Map) | 이름이 내용을 말한다 (G-02) |
| Events | 재난 (Disasters) | 일반 사용자의 말 |
| Overview | 현황 (Overview) | 맨 뒤로. 보조 화면이다 |
| Connect, Plan, Challenges | 참여 (Take part) 아래 3개 | "돕는 방법"으로 묶는다 (G-01) |
| About | 계정 메뉴와 페이지 하단 | 주 메뉴에서 뺀다 |
| 언어, 로그인, 설정 | 계정 메뉴 하나 | 헤더 오른쪽을 2개로 줄인다 (G-05) |

- 계정 메뉴: 로그인 전에는 `로그인`, `언어`, `설정`, `소개`. 로그인 후에는 `내 활동(/connect/mine)`이 추가된다.
- "참여"를 누르면 새 화면 `/act`가 열린다(5.4). 화살표를 누르면 하위 3개가 펼쳐진다.
- 모바일: 하단 탭 4개(지도, 재난, 참여, 현황). 햄버거 메뉴에는 계정 항목만 남긴다.
- "Back to Map" 링크는 없앤다(G-06). 헤더가 그 역할을 한다.

### 4.2 필터는 하나다

지도와 목록이 같은 필터 상태를 쓴다(L-06). 유형, 심각도, 기간, 검색어를 URL 쿼리(`?types=flood&sev=high,critical&q=…`)에
담고, `/`와 `/events`를 오갈 때 쿼리를 그대로 넘긴다. `hooks/useMapUrlState.ts`와 `lib/map/urlState.ts`가 이미 지도 상태를 URL에 쓰고 있으니
거기에 합친다.

### 4.3 숫자의 정의는 하나다

"활성 재난"은 `is_active = true`인 이벤트 수다. 인트로, 지도, 목록, 대시보드가 모두 이 정의를 쓴다(G-03).
종료된 이벤트를 포함한 수를 보여 줄 때는 "전체 234건(진행 중 223건)"처럼 둘을 함께 쓴다.

**마커 (M-01)**
- 색은 심각도다. `globals.css`의 `--sev-low/medium/high/critical`을 그대로 쓴다.
- 유형은 마커 안의 아이콘으로 표시한다(지금 목록에서 쓰는 유형 아이콘과 같은 것).
- 묶음의 색은 그 안에서 가장 높은 심각도를 따른다. 숫자는 건수다. 크기는 건수에 따라 3단계.
  MapLibre 클러스터 속성(`clusterProperties`)으로 최고 심각도를 집계한다.
- 범례는 "색 = 심각도" 4칸과 "아이콘 = 유형"(현재 화면에 있는 유형만)으로 다시 그린다.
- 심각·높음 마커는 항상 낮은 등급 위에 그린다(`symbol-sort-key`).

**왼쪽 패널 (M-02, M-03, M-07, M-09)** — 탭 두 개.

- **재난 탭**
  - 맨 위: "화면 안 137건 · 심각 10 · 높음 11". 누르면 오른쪽 패널에 그 목록이 열린다(심각도순, 항목을 누르면 지도가 이동).
  - 심각도: 칸 4개, 각 칸에 건수.
  - 유형: 건수가 있는 유형만 건수와 함께 보여 준다. 0건인 유형은 "다른 유형 12개" 아래에 접는다.
  - "모두 선택 / 모두 해제" 버튼.
- **레이어 탭** — 4개 묶음으로 나누고, 켜짐·꺼짐은 스위치로 표시한다.

  | 묶음 | 레이어 |
  |---|---|
  | 위험 | 열대 저기압, 지진 흔들림, 산불, 강수 레이더 |
  | 위성 영상 | 위성 사진, 적외선 구름, 야간 조명 |
  | 기반 시설 | 병원, 발전소, 댐, 해저 케이블 |
  | 실시간 관측 | 항공기, 선박, 교통 카메라, 관측 위성, 우주 발사 |

  이름은 쉬운 말로 쓴다("항공기"). 출처와 조건("ADS-B · 확대 5 이상에서 표시")은 이름 아래 작은 글씨로 내린다.
  확대 조건 때문에 지금 안 보이는 레이어는 "더 확대하면 보입니다"라고 쓴다.
  투명도 조절은 켜진 레이어에만 보인다.
- **데이터 출처**는 패널에서 빼고, 지도 위 "실시간" 표시를 누르면 열리는 작은 창으로 옮긴다.
  "No data yet"은 회색 "수집 전"으로 바꾼다. 경고색은 수집이 실패했을 때만 쓴다.

**지도 위 도구 (M-04)**
- 아이콘 5개를 `보기 ▾` 하나로 모은다. 안에 `2D / 3D`, `지도 / 위성`, `보기 모드`, `정밀 3D 엔진`이 이름과 함께 있다.
- `공유`는 이름이 보이는 버튼으로 따로 둔다.

**재난 요약 패널 (M-05)** — 마커를 눌렀을 때. 위에서부터 이 순서다.
1. 심각도 배지, 유형, 제목
2. 장소(나라·지역 이름), 발생 시각("3시간 전 · 11월 14일 03:18 UTC"), 진행 단계 한 단어
3. 피해 규모(있을 때만): 영향 인구, 피해 면적
4. 주 버튼 **`자세히 보기`** → `/events/[id]`
5. 보조 버튼: `도움 주기`, `이 지역 알림`
6. 접힌 항목: `신뢰도 60% · 출처 1곳`(펼치면 지금의 단계 표시), `브리핑 듣기`, `주변 라디오`, `길 찾기`

**지도 도우미 (M-06)**: `/api/v1/agent/status`가 사용 불가를 돌려주면 "Ask the map" 버튼을 그리지 않는다.
사용할 수 있을 때는 오른쪽 패널 자리에 열고, 재난 요약 패널과 겹치지 않게 한다.

**기간 (M-08)**: 타임라인 왼쪽에 기간 이름("최근 30일")을, 손잡이 아래에 날짜를 쓴다. 막대 위에 올리면
"11월 9일 · 96건"이 나온다. 처음에는 접힌 상태(`기간: 최근 30일 ▾`)로 두고 누르면 펼친다.

**처음 열었을 때 (M-10, G-04)**
- 지구가 지도 영역 높이의 85%를 채우도록 초기 확대값을 화면 크기에 맞춘다.
- 처음 방향은 브라우저 시간대에서 추정한 경도다(위치 권한을 묻지 않는다).
- 인트로는 기기당 한 번만 보여 준다(`localStorage`). 3초 뒤 자동으로 넘어가고, `건너뛰기`가 있다.
  `/?event=…`처럼 특정 상태로 들어온 주소에서는 인트로를 건너뛴다.

**모바일 (M-11)**
- 지도 위에는 `실시간` 표시, 확대·축소, `필터` 버튼, `보기` 버튼만 둔다.
- 하단에 끌어올리는 시트 하나를 둔다. 접힌 상태에서는 "화면 안 86건 · 심각 5" 한 줄이다. 올리면 목록이 나온다.
  마커를 누르면 같은 시트에 재난 요약이 나온다.
- 타임라인과 범례는 `보기` 안으로 옮긴다. 지도 저작권 표시는 가리지 않는다.

### 5.2 재난 목록 (`/events`)

- **기본 정렬은 "중요도순"이다(L-01).** 심각도 내림차순, 같은 등급 안에서는 영향 인구, 그다음 최신순.
  정렬 선택: `중요도순`, `최신순`, `영향 인구순`. API(`apps/api/src/api/v1/events.py`)에 `sort` 파라미터를 추가한다.
- 화면 위쪽에 검색창을 둔다(L-05). 헤더 검색과 같은 `q`를 쓴다.
- 필터 칸: 심각도 4개(건수 포함), 유형은 건수가 있는 것만(건수 포함), 나머지는 `유형 더 보기`.
  선택된 칸은 채운 배경으로 표시한다(L-04). 기간 선택(`24시간`, `7일`, `30일`, `전체`)을 추가한다.
- 데스크톱은 카드 3열 대신 **한 줄에 한 건인 목록**으로 바꾼다. 한 화면에 12건 이상 보인다.

  ```
  ● 심각  홍수   모잠비크·남아공 홍수                 모잠비크      영향 12만 명   3일 전
  ● 높음  지진   M 6.1 — 수마트라 서쪽 해안           인도네시아    집계 전        1시간 전
  ```
  - 왼쪽 색 막대가 심각도다. 배지는 심각도 하나만 남긴다(R-04).
  - 장소는 나라·지역 이름이다(L-03). `country`가 비어 있으면(USGS) 제목에서 "of" 뒤의 지명을 쓴다.
    좌표는 상세 화면에만 둔다.
  - 설명이 제목과 같은 내용이면 보여 주지 않는다(L-02).
- 모바일은 같은 정보를 두 줄 카드로 보여 준다.
- `지도에서 보기`는 현재 필터를 유지한 채 `/`로 간다(L-06).
- 50건씩 불러오고, 아래에 `더 보기`를 둔다. 맨 위에는 "223건 중 50건"을 쓴다.

### 5.3 재난 상세 (`/events/[id]`) — 허브

**머리 부분 (항상 보인다)**

```
← 재난 목록
● 심각 · 홍수 · 대응 단계
모잠비크·남아공 홍수
모잠비크 가자주 · 11월 11일 시작 · 3일째                    [도움 주기] [부지 설계] [알림 받기] [공유]
┌─────────┬─────────┬─────────┬─────────┐
│ 영향 인구 │ 피해 면적 │ 필요 등록 │ 신뢰도   │
│ 12만 명  │ 집계 전   │ 4건      │ 60% · 1곳│
└─────────┴─────────┴─────────┴─────────┘
```

- 행동 버튼은 제목 옆에 둔다(E-02). 스크롤하면 화면 위에 붙는다. 모바일에서는 화면 아래에 붙는다.
- 요약 4칸: 값이 없으면 "집계 전"이라고 쓴다(원칙 3). 신뢰도는 여기서 한 칸으로 줄이고(E-03), 누르면 설명이 펼쳐진다.

**탭 4개** (탭 이름 옆에 건수)

| 탭 | 내용 | 비어 있을 때 |
|---|---|---|
| 상황 | 위치 지도, 상황 보고서, 피해 평가, 전후 위성 비교, 출처 | 아래 규칙 |
| 필요와 지원 (4) | 이 재난의 필요 목록, 지원 제안 버튼, 단체의 진행 소식 | 3단계 안내와 `필요 등록` / `지원 제안` |
| 설계 (2) | 부지 계획, 이 재난의 설계 공모 | "첫 부지 계획을 시작해 보세요"와 `부지 설계` |
| 소식 | 진행 소식을 시간순으로 | "아직 올라온 소식이 없습니다" 한 줄 |

**빈 섹션 규칙 (E-01)**: 데이터가 없는 섹션은 큰 카드로 그리지 않는다. "상황" 탭 맨 아래에
"아직 없는 정보" 묶음으로 모아 한 줄씩 쓴다.

```
아직 없는 정보
· 피해 평가 — Copernicus EMS가 이 재난에 대응하면 표시됩니다
· 전후 위성 비교 — 이 지역의 영상을 찾지 못했습니다  [날짜 직접 고르기]
```

- 전후 비교(E-04): 기본값은 "발생 7일 전"과 "영상이 있는 가장 최근 날짜"다. 영상이 없으면 섹션을 위 묶음으로 내린다.
- 상황 보고서(E-05): 값이 없는 항목은 빼고 한 단으로 그린다. `복사`, `인쇄`는 유지한다.
- "상황" 탭의 위치 지도는 재난 범위가 보이는 확대 수준으로 열고, 피해 범위(GeoJSON)가 있으면 함께 그린다.

### 5.4 참여 (`/act` 신설, `/connect`, `/plan`, `/challenges`, `/alerts`)

**`/act` — 참여 첫 화면 (A-01, A-06)**
- 맨 위: "어떻게 도울 수 있나요?" 카드 3개.
  `필요한 곳에 지원하기 →`, `구호 부지 설계하기 →`, `설계 공모 참여하기 →`. 카드마다 한 문장 설명과 현재 건수.
- 그 아래: **도움이 필요한 재난** 목록. 필요가 등록된 재난, 없으면 심각도가 높은 진행 중 재난 5건.
  각 줄에서 재난 상세의 "필요와 지원" 탭으로 간다.
- 로그인한 단체 사용자에게는 `우리 단체의 필요 등록하기`가 맨 위에 나온다.

**필요와 지원 (`/connect`)**
- 빈 상태를 3단계 안내로 바꾼다: ① 승인된 현장 단체가 필요를 올린다 ② 누구나 지원을 제안한다
  ③ 양쪽이 동의하면 연락처가 공유된다. 그 아래에 `지원 제안하기`와 `단체 등록 신청`.
  "My connections" 같은 내부 메뉴 이름은 문구에서 뺀다.
- 필요 카드에 재난 이름을 넣고, 누르면 그 재난으로 간다. 재난별로 걸러 볼 수 있다.

**부지 설계 (`/plan`) (A-02, A-03, A-04)**
- 재난 없이 열면 지도 대신 시작 화면을 보여 준다: "어느 재난의 부지를 설계하나요?"
  진행 중인 재난 검색, 장소 검색, `빈 지도에서 시작`. 재난 상세에서 들어오면(`/plan?event=…`) 그 위치로 바로 연다.
- 화면 위에 "모잠비크·남아공 홍수 · 부지 계획" 맥락을 항상 표시한다.
- 도구 6개에 이름을 붙인다(`천막`, `급수`, `화장실`, `진료소`, `창고`, `지우기`). 고른 도구의 안내는 지도 위쪽 가운데에 쓴다.
- 기준 점검표: 아무것도 놓지 않았을 때는 회색 "시작 전"이다. 하나라도 놓으면 `충족`(녹색 ✓), `부족`(주황, 얼마나 모자란지)으로 표시한다. 빨간 ✕는 쓰지 않는다.
- 모바일: 지도가 전체 화면이고, 점검표는 아래 시트("기준 3/8 충족" 한 줄, 올리면 전체)다. 도구는 지도 아래쪽에 가로로 놓는다.

**지역 알림 (`/alerts`) (A-05)**
- 지역 추가는 세 가지 방법: `장소 검색`, `지도에서 고르기`(작은 지도에서 눌러서 원으로 범위 표시), `현재 위치`.
  위도·경도 입력칸은 `직접 입력` 아래에 접는다.
- 재난 상세나 지도에서 `알림 받기`를 누르면 이름·위치·범위가 채워진 채로 열린다.
- 알림 켜기 두 단계("브라우저 알림", "Phoenix를 닫았을 때 알림")를 하나의 설정 묶음으로 합치고, 각각 무엇이 달라지는지 한 문장으로 쓴다.

**설계 공모 (`/challenges`)**: 빈 상태에 예시 하나("X 지역 1,000명 임시 거주지 설계")와 진행 방식 3단계(제출 → 투표 → 선정)를 보여 준다.

### 5.5 현황 (`/dashboard`)

- 값이 없는 지표는 0 대신 "집계 전"으로 쓰고, 큰 숫자 자리에 두지 않는다(D-01). 맨 앞 큰 칸은 값이 있는 "진행 중인 재난"이 차지한다.
  영향 인구는 "추정치가 있는 재난 N건 기준"이라는 조건을 함께 쓴다.
- 숫자와 막대를 누르면 그 조건이 걸린 재난 목록으로 간다(D-03). 예: 심각 12 → `/events?sev=critical`.
- 비어 있는 차트는 "표시할 데이터가 없습니다" 한 줄로 줄인다(D-02).

## 6. 가독성 규칙 (전 화면 공통)

| 항목 | 규칙 |
|---|---|
| 글자 크기 | 본문 15~16px, 보조 14px, 가장 작은 글씨 13px. 11~12px은 쓰지 않는다 (R-01) |
| 글자 색 | 어두운 배경의 본문은 `gray-100`, 보조는 `gray-300`. `gray-400` 이하는 비활성 상태에만 쓴다. WCAG AA(4.5:1)를 지킨다 |
| 카드 | 배경과 테두리의 차이를 키운다. 카드 안에 카드를 넣지 않는다 (R-02) |
| 시간 | 한 가지 형식: 목록은 "3시간 전", 상세는 "3시간 전 · 11월 14일 03:18 UTC". `lib/format.ts`의 함수 하나만 쓴다 (R-03) |
| 숫자 | 큰 수는 줄여 쓴다("12만 명", "120K"). 없는 값은 "집계 전". 0은 실제로 0일 때만 |
| 색 | 심각도 색 4개는 심각도에만 쓴다. 주 행동 버튼은 녹색(`--regrow`) 하나. 화면당 주 버튼은 하나 |
| 누르는 영역 | 최소 44×44px. 아이콘만 있는 버튼에는 `aria-label`과 툴팁 |
| 빈 상태 | `components/ui/States.tsx`의 공통 컴포넌트를 쓴다. "왜 비었는지 + 무엇을 할 수 있는지"를 한 문장씩 |
| 움직임 | `prefers-reduced-motion`과 설정의 "애니메이션" 값을 따른다 |
| 밝은 테마 | 모든 변경은 밝은 테마에서도 확인한다. 색은 CSS 변수만 쓴다 |

## 7. 구현 단계

각 단계는 따로 병합할 수 있다. 순서는 "잘못된 정보 고치기 → 구조 → 화면" 순이다.
모든 단계의 공통 완료 조건: 타입 체크 통과, 웹 단위 테스트 통과, 새 문구가 7개 언어에 모두 있음,
1440×900과 390×844에서 화면 캡처로 확인, 밝은 테마 확인.

### 1단계 — 잘못된 정보 고치기 (작고 빠르다)

> 구현 완료 (2026-11-14, `feat/ux-stage1`). 마커 아이콘은 `lib/eventTypeIcons.ts` 하나에서 나오고, 목록·사이드바·상세가
> 같은 아이콘을 쓴다. 대시보드용으로 API `GET /api/v1/stats/overview`에 `affected_estimated`(추정치가 있는 진행 중 재난 수)를 추가했다.

| 작업 | 해결 | 완료 조건 |
|---|---|---|
| 마커·묶음 색을 심각도로, 범례 다시 그리기 | M-01 | 심각 재난이 든 묶음은 심각 색이다. 범례의 색이 지도와 같다 |
| "활성 재난" 숫자 정의 통일 | G-03 | 인트로, 범례, 대시보드의 숫자가 같다 |
| 0 대신 "집계 전" | D-01, D-02 | 추정치가 없는 DB에서 대시보드에 "0명"이 나오지 않는다 |
| 지도 도우미 버튼 조건부 표시 | M-06 | AI 키가 없으면 버튼이 없다 |
| 인트로를 기기당 한 번, 자동 넘김 | G-04 | 두 번째 방문에서는 지도가 바로 열린다 |
| 출처 상태 문구와 색 | M-09 | "수집 전"은 회색이다 |
| 아이콘 버튼에 이름 | M-04, A-04 | 지도·Plan의 모든 도구에 보이는 이름이나 툴팁이 있다 |

### 2단계 — 메뉴와 공통 규칙

- 헤더를 4.1대로 바꾼다. 계정 메뉴, 모바일 하단 탭.
- 6장의 글자 크기·색 규칙을 `globals.css`와 공통 클래스에 반영한다. 시간·숫자 표기 함수를 하나로 모은다.
- 완료 조건: 헤더 항목이 4개 + 검색 + 알림 + 계정이다. 12px 미만 글씨가 없다.

### 3단계 — 필터 통합과 재난 목록

- 4.2의 공통 필터 상태(URL 쿼리)를 만들고 지도와 목록에 연결한다.
- API에 `sort`와 유형·심각도별 건수(필터 칸에 쓸 값)를 추가한다. 5.2대로 목록을 다시 만든다.
- 완료 조건: 목록에서 "홍수 + 높음 이상"을 고르고 `지도에서 보기`를 누르면 지도에 같은 필터가 걸려 있다.
  기본 정렬에서 심각 재난이 맨 위에 있다.

### 4단계 — 지도 패널

- 5.1의 왼쪽 패널(탭, 건수, 레이어 묶음), 오른쪽 패널(화면 안 목록, 재난 요약), `보기` 메뉴, 기간 표시.
- 완료 조건: 0건 유형이 접혀 있다. 재난 요약 패널의 주 버튼이 `자세히 보기`다. 요약 패널과 도우미가 겹치지 않는다.

### 5단계 — 재난 상세 허브

- 5.3의 머리 부분, 요약 4칸, 탭 4개, 빈 섹션 규칙, 붙는 행동 버튼.
- 완료 조건: 부가 데이터가 없는 재난의 "상황" 탭이 1440×900에서 2화면 이내다. 행동 버튼이 스크롤 없이 보인다.

### 6단계 — 참여 흐름

- `/act` 신설, Connect 빈 상태, Plan 시작 화면과 점검표 상태, Alerts 지역 선택, Challenges 빈 상태.
- 완료 조건: 재난 상세 → `부지 설계`를 누르면 그 재난 위치에서 Plan이 열리고 화면에 재난 이름이 보인다.
  Alerts에서 숫자를 입력하지 않고 지역을 추가할 수 있다.

### 7단계 — 모바일 마무리

- 지도 하단 시트, Plan 하단 시트, 하단 탭과의 겹침 정리.
- 완료 조건: 390×844 지도 화면에서 지도가 보이는 영역이 화면 높이의 65% 이상이다. 저작권 표시가 가려지지 않는다.

### 구현할 때 주의

- 개발 서버(`next dev`)가 떠 있을 때 `pnpm run build`를 돌리면 `.next`가 섞여 개발 서버가 깨진다.
  빌드 검사 뒤에는 `apps/web/.next`를 지우고 개발 서버를 다시 띄운다.
- 지도 관련 변경 뒤에는 `apps/web/scripts/perf-map.mjs`로 렌더링 성능을 다시 잰다.
- 기존 Playwright 테스트 11개는 헤더 메뉴 이름에 의존할 수 있다. 2단계에서 함께 고친다.

## 8. 이번 범위가 아닌 것

- 새 기능(자체 AI 피해 모델, 기부 추적, 3D 모델 배치 도구). 이 문서는 이미 있는 기능의 구조와 표현만 다룬다.
- 브랜드 색과 로고 변경. 색 체계는 그대로 두고 쓰는 규칙만 정한다.
- 백엔드 데이터 보강(USGS 이벤트의 나라 이름 채우기 등). 5.2의 제목 기반 대안으로 우선 해결하고, 보강은 따로 다룬다.
